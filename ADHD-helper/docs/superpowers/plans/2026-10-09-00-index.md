# ADHD Helper — Implementation Plan Index

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement each phase plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the native Android + Linux desktop task app with a Claude assistant described in the spec, in seven phases that each end in working, tested software.

**Architecture:** One Gradle build. `shared/` (Kotlin Multiplatform android+jvm: models, sync rules, recurrence, client DB, repository, sync client; no Compose), `ui/` (Kotlin Multiplatform android+jvm, Compose Multiplatform screens, package `com.sagunkayastha.adhdhelper.ui`, `api(project(":shared"))`), `androidApp/` and `desktopApp/` (both depend on `:ui`), `server/` (Ktor, depends on `:shared` only, so the server jar never pulls in Compose). Clients keep a local SQLite DB and sync by last-writer-wins on a hybrid logical clock; the server runs the `claude` CLI against its own MCP endpoint.

**Tech Stack:** Kotlin 2.2.0, Compose Multiplatform 1.8.2, Ktor 3.2.0, SQLDelight 2.1.0, kotlinx-serialization 1.9.0, kotlinx-coroutines 1.10.2, kotlinx-datetime 0.7.1, AGP 8.11.1, Gradle 8.14.3, JDK 21 (build) / JRE 21 (server), Android compileSdk 35 / minSdk 29.

**Spec:** `docs/superpowers/specs/2026-10-09-adhd-helper-design.md`

## Global Constraints (apply to every phase)

- **Docker-only:** every build, test, and tool runs inside the build container (`docker/build.Dockerfile`, image `adhd-build`). Nothing is installed on the host (no JDK, Gradle, Android SDK, Node). Standard test command (runs as the host user so `build/`, `.gradle/`, `.kotlin/` are never root-owned; Gradle cache in volume `adhd-gradle` at `/gradle`):
  `docker run --rm --user "$(id -u):$(id -g)" -e GRADLE_USER_HOME=/gradle -v adhd-gradle:/gradle -v "$PWD":/src -w /src adhd-build gradle <task> --no-daemon`
  One-time setup (Phase 1 Task 1): `docker volume create adhd-gradle && docker run --rm -v adhd-gradle:/gradle alpine chown "$(id -u):$(id -g)" /gradle`. The image sets `HOME=/tmp`, accepts the Android SDK licenses at build time and leaves the SDK world-readable (`chmod -R a+rX`), so any uid can build.
- **Never bind `0.0.0.0` on archbox.** The host's `tailscale0` is the employer tailnet. Publish only `192.168.0.162:8020`.
- **Secrets:** `CLAUDE_CODE_OAUTH_TOKEN` only in `~/stacks/tasks/.env` (0600) with placeholder `YOUR_TOKEN_HERE`; never committed, never logged. Device tokens are never logged.
- **No files in `~`** on any host except the agreed `~/stacks/tasks/` on archbox.
- Package root: `com.sagunkayastha.adhdhelper`. App name: `ADHD Helper`.
- Time zone for wall-clock due times: `America/Denver` (setting `zone`, default that value).
- Gradle catalog aliases are Phase 1's camelCase names (`libs.plugins.kotlinMultiplatform`, `kotlinJvm`, `kotlinSerialization`, `androidApplication`, `androidLibrary`, `composeMultiplatform`, `composeCompiler`, `sqldelight`, `ktor`; Phase 4 adds `kotlinAndroid`), all declared `apply false` in the root build. No hard-coded dependency coordinates in module builds.
- Reminder actions: Android notifications show **Done / Snooze 10 min / Snooze 1 h** (Android renders at most three buttons); **Tomorrow 9am** is a desktop `notify-send` action and, on both platforms, a "Snooze until tomorrow 9am" button on the task detail screen.
- APK version files: `version.txt` holds the integer `versionCode` only (matches `Health.apkVersion: Int`); the `versionName` goes in `version-name.txt` next to it. The server reads `version.txt` on every request.
- If a pinned dependency version fails to resolve, use the nearest newer patch release of the same minor and note it in the commit message; never jump minors silently.
- Commits end with:
  ```
  Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
  Claude-Session: https://claude.ai/code/session_0143tpSGVgH2wyDhkxyE99yr
  ```

```kotlin
interface Versioned { val id: String; val hlc: String }

@Serializable enum class Freq { DAILY, WEEKLY, MONTHLY, YEARLY }
@Serializable data class RepeatRule(val freq: Freq, val every: Int = 1, val days: List<DayOfWeek> = emptyList(),

    override val id: String, val title: String, val sortKey: String,
    override val hlc: String, val deleted: Boolean = false) : Versioned

@Serializable data class Task(

    val dueDate: LocalDate? = null, val dueTime: LocalTime? = null,
    val repeat: RepeatRule? = null, val completedAt: Instant? = null,
    val sortKey: String, val snoozeUntil: Instant? = null,
    override val hlc: String, val deleted: Boolean = false) : Versioned

@Serializable data class Note(
    override val id: String, val text: String, val createdAt: Instant,
    val taskId: String? = null, override val hlc: String, val deleted: Boolean = false) : Versioned

@Serializable enum class Role { USER, ASSISTANT }
@Serializable enum class ChatStatus { QUEUED, SENT, ANSWERED, FAILED }
@Serializable data class ChatMessage(
    override val id: String, val role: Role, val text: String, val createdAt: Instant,
    val status: ChatStatus, override val hlc: String) : Versioned
```

    fun now(): String            // format "%015d-%05d-%s" (millis, counter, nodeId); strictly increasing per instance
    fun observe(remote: String)  // advance local state past a received hlc

### `.../core/` (Phase 1)

```kotlin
object SortKey { fun between(before: String?, after: String?): String }  // before < result < after; null = open end
object Recurrence { fun next(rule: RepeatRule, from: LocalDate): LocalDate }
    // first occurrence strictly after `from`. MONTHLY/YEARLY land on rule.anchorDay ?: from's day, clamped to the
    // month length: anchor 31 gives Jan 31 -> Feb 28 -> Mar 31; yearly anchor 29 gives Feb 29 -> Feb 28 (non-leap) -> Feb 29 (leap)
object ReminderMath { fun nextFire(task: Task, zone: TimeZone, now: Instant): Instant? }
    // null if deleted, completed, dueDate null or dueTime null. Otherwise due = dueDate+dueTime in `zone`;
    // returns snoozeUntil if snoozeUntil != null && snoozeUntil > due, else due.
    // `now` is kept in the signature but does not affect the result: callers compare the result with now
    // (fire at once / skip / schedule). The result may be in the past.
object Completion {                                                       // Phase 3 (shared core; reused by Phase 6 server tools)
    fun nextOccurrence(task: Task, sortKey: String, hlc: String): Task?   // null if no repeat or no dueDate; id Ids.derived("${task.id}:${nextDate}"),
                                                                          // dueDate = Recurrence.next, same list/parent/title/details/starred/dueTime/repeat,
                                                                          // completedAt = null, snoozeUntil = null
    fun anchored(task: Task): Task   // MONTHLY/YEARLY rule with anchorDay == null and a dueDate -> anchorDay = dueDate.day; else unchanged
}
object Api { const val PREFIX = "/api/v1"; const val VERSION = 1 }
@Serializable data class PairRequest(val code: String, val deviceName: String)
@Serializable data class PairResponse(val token: String, val deviceId: String)   // deviceId: server's label for the pairing (tasks devices/revoke); informational, clients never store it
@Serializable data class Health(val ok: Boolean, val rev: Long, val claude: String, val apkVersion: Int? = null)
```

## Review Focus (cross-phase; each owning plan adds the pinning test)

1. **Same task edited offline on phone and PC, then both sync** — both converge to the later-HLC version; no duplicate, no resurrection of a deleted task. (Phase 3 convergence test.)
2. **Reminder across DST and phone reboot** — a daily 18:00 task fires at 18:00 local on both sides of the March/November switch, and alarms survive reboot. (Phase 1 ReminderMath test; Phase 4 boot-receiver test.)
3. **Completing a repeating task twice quickly / on two devices** — exactly one next occurrence exists after sync. (Phase 3: next occurrence id is `Ids.derived("${id}:${nextDate}")` via `Completion.nextOccurrence`, so both devices and the server create the same row.)
4. **Assistant down or token missing** — the user's message is still saved as a note, marked FAILED, retryable; `/health` reports `claude: unauthenticated`. (Phase 6.)
5. **Server unreachable for days** — local edits keep working, the pending chip counts them, and the first sync after return succeeds (cursor older than tombstone purge → `fullResync`). (Phase 2 purge test + Phase 3 full-resync test.)
6. **Concurrent writers on one phone** (UI, notification action, WorkManager at once) — HLC stamps stay unique and ordered. (Phase 3 `parallelAddTaskCallsGetDistinctOrderedHlcs`.)
7. **Monthly task on the 31st / yearly on Feb 29** — returns to the anchor day after a short month. (Phase 1 `RecurrenceTest`, Phase 3 `monthly31stWalksBackToThe31st`, Phase 6 `monthlyRepeatIsAnchoredToItsDueDay`.)
